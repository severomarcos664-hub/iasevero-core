## 7. Version-closeout contract

For every future official version, continuity closeout MUST evaluate:

- official tag;
- exact commit;
- changed architectural owner;
- specific proof;
- relevant regressions;
- new guarantee;
- explicit limitation;
- baseline advancement;
- Architecture Ledger impact;
- Advanced Technology Registry impact.

The official baseline MUST NOT be advanced in continuity metadata before Git preservation and convergence are proved.

---

## 8. Historical-confidence rule

Older tags remain valid historical Git evidence.

However, an older capability claim MUST NOT automatically be treated as the current implementation state when later versions may have changed the architecture.

When current-state accuracy matters, prefer the latest applicable proof and current canonical owner.

---

## 9. Anti-drift rule

A future chat MUST NOT:

- invent a commit hash;
- infer a tag from version naming;
- call a work branch an official baseline;
- treat an unpushed commit as remotely preserved;
- treat a historical tag as proof of current behavior without checking later evolution;
- promote roadmap to implementation because a similar filename exists.
